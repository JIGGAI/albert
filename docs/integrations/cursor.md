# Cursor integration

## Automatic memory adapter

Albert ships a command-hook fixture at `src/albert/cursor_hooks/hooks.json` and
an always-applied rule at `src/albert/cursor_rules/albert-memory.mdc`. Install
the Python package, copy the hook fixture to `.cursor/hooks.json` (project) or
merge it into `~/.cursor/hooks.json` (user), and copy the rule to
`.cursor/rules/albert-memory.mdc`. The fixture invokes
`albert-cursor-adapter`; no Cursor internals are patched.

Required secret-backed environment variables:

- `ALBERT_CAPTURE_TOKEN`: an Albert credential limited to context read and capture write.
- `ALBERT_CAPTURE_QUEUE_KEY`: a URL-safe 32-byte AES key generated by
  `albert.capture_sdk.generate_queue_key()` and stored in the operator's secret store.

Optional variables are `ALBERT_API_URL`, `ALBERT_WORKSPACE_ID`,
`ALBERT_CAPTURE_SCOPE`, `ALBERT_CAPTURE_QUEUE_PATH`, `ALBERT_CAPTURE_TIMEOUT`
(capture requests, default 1 second), and `ALBERT_RECALL_TIMEOUT` (recall
requests, default 4 seconds). The encrypted queue defaults to
`~/.cursor/albert/capture.db`; the adjacent sequencing database contains only
hook identities, event classes, and sequence numbers.

The adapter uses only Cursor's documented version-1 command hooks:
`sessionStart`, `beforeSubmitPrompt`, `preCompact`, `afterAgentResponse`,
`stop`, and `sessionEnd`. Start recall is bounded, cited, delimited, and
explicitly non-authoritative. Captured content is limited to the current user
goal, final assistant response, observed lifecycle counts/status/reason, and
minimized VCS provenance. The adapter deliberately does not read
`transcript_path`, attachments, thought blocks, tool bodies, complete
transcripts, user email, or absolute workspace paths. Known credential
material is rejected before durable queueing, and Albert outages return an
empty successful hook response so work continues.

`beforeSubmitPrompt` does not support context injection, so recall is injected
only by `sessionStart`. `stop` exposes status but no error details; an error
status is recorded only as the observed generic status. It is never expanded
into an inferred failure cause. `afterAgentResponse` supplies the supported
final response checkpoint, while `sessionEnd` supplies the true IDE/CLI
session boundary.

### Compatibility and reduced fidelity

| Cursor surface/version | Available lifecycle | Status |
| --- | --- | --- |
| Desktop 3.27.22, hooks schema v1 | All six fixture hooks, including start recall and session end | Tested fixture against the published 3.27.22 stable schema |
| Agent CLI 2026.10.22-27dcf5f | All six fixture hook identifiers are present in the released CLI | Binary/version and packaged hook surface verified |
| Self-hosted cloud workers on the 2026-10-22 surface | Same project command hooks after the worker becomes writable; start/end fire when a worker claim starts/ends | Supported with worker timing disclosed |
| Cursor cloud agents on the 2026-10-22 surface | Prompt, compaction, response, and stop only | Reduced fidelity: no start recall or true end event |
| Other Cursor versions | Re-run the fixture against that version's documented schema before release | Unverified |

Cloud agents do not expose `sessionStart` or `sessionEnd`; Albert therefore
does not fabricate either event on that surface. A cloud run still captures
supported prompt, compaction, response, and stop checkpoints. Because no
documented start hook runs there, automatic start recall is unavailable; use
the MCP tools under the rule below when recall is needed.

The end-to-end fixture is `tests/test_cursor_adapter.py`. It proves bounded
cited start recall, retry idempotency and sequence preservation, prompt and
response minimization, compaction/stop/end checkpoints, generic observed
failure status, outage queueing, secret non-retention, ignored transcript and
attachment fields, the version-1 hook manifest, and the reduced-fidelity
disclosure.

## MCP tools

Cursor reads MCP definitions from `.cursor/mcp.json` for one project or
`~/.cursor/mcp.json` for all projects.

## Local stdio

```json
{
  "mcpServers": {
    "albert": {
      "command": "/absolute/path/to/albert-mcp",
      "args": ["--transport", "stdio"],
      "env": {
        "ALBERT_API_URL": "http://127.0.0.1:8080",
        "ALBERT_MCP_API_KEY": "REPLACE_FROM_SECRET_STORE"
      }
    }
  }
}
```

## Protected remote endpoint

```json
{
  "mcpServers": {
    "albert": {
      "url": "https://memory.internal.example/mcp",
      "headers": {
        "Authorization": "Bearer REPLACE_FROM_SECRET_STORE"
      }
    }
  }
}
```

Do not commit a project-level file containing a credential. Prefer Cursor's
secret-backed environment substitution when available; the gateway forwards
the bearer key so each client keeps its own Albert principal and audit identity.

After saving the configuration, open Cursor's MCP settings and verify that the
Albert tools appear. Use the shipped `albert-memory.mdc` rule (or adapt
[AGENTS.example.md](AGENTS.example.md)) so MCP recall remains cited and
non-authoritative.

References: [Cursor hooks](https://cursor.com/docs/agent/hooks) and
[Cursor MCP](https://docs.cursor.com/context/model-context-protocol).
