# Claude Code integration

Albert ships a Claude Code plugin fixture at `src/albert/claude_plugin`. The
supported lifecycle command validates the installed Claude Code version and
plugin schema, writes credentials only to an owned mode-0600 file, atomically
replaces Albert-owned state, proves direct-Brain capture and fresh-session
recall, and creates an isolated launcher:

```bash
albert-claude-lifecycle install --api-url https://brain.example
~/.claude/albert/bin/albert-claude
albert-claude-lifecycle doctor --smoke
```

The token is collected with a hidden prompt. It is never accepted as an
argument, ordinary environment option, Claude setting, log, diagnostic, or
artifact. Automation may instead provide private standard input or a private
file descriptor with `--token-stdin` or `--token-fd`. The launcher uses Claude
Code's documented `--plugin-dir` surface and does not edit user settings.

## Connect from Albert Cloud

In Albert Cloud, open the Brain's **Agents** tab, choose **Claude Code**, and create a
setup link. The link is single-use, expires in 15 minutes, and is signed for
Claude Code only. Let the command prompt for it so it stays out of shell history and
process arguments:

```bash
albert-claude-lifecycle connect
albert-claude-lifecycle doctor --smoke
```

`connect` verifies the signed manifest and package version, redeems the link for
a credential limited to capture and recall in the chosen workspace, and then runs
the same transactional install and live smoke test as `install`. If anything
fails, the previous installation is restored and the new credential is revoked
through Cloud. Automation may pass the link with `--link-stdin` or `--link-fd`.
Start Claude Code with `~/.claude/albert/bin/albert-claude` afterwards.

## Development

For source-tree development, validate and load the fixture directly:

```bash
claude plugin validate --strict src/albert/claude_plugin
claude --plugin-dir src/albert/claude_plugin
```

Manual beta installs may still provide these variables through an operator's
secret-backed environment:

- `ALBERT_CAPTURE_TOKEN`: an Albert credential limited to context read and capture write.
- `ALBERT_CAPTURE_QUEUE_KEY`: a URL-safe 32-byte AES key generated by
  `albert.capture_sdk.generate_queue_key()`.

The plugin also bundles Albert's MCP server (`.mcp.json`, stdio via
`albert-mcp`), so the agent can search, assemble context, query the graph and
remember on demand. Set `ALBERT_MCP_API_KEY` to a least-privilege key for it;
`ALBERT_API_URL` defaults to `http://127.0.0.1:8080`. Without a key the MCP
server reports an error and the hooks keep working.

Optional variables are `ALBERT_API_URL`, `ALBERT_WORKSPACE_ID`,
`ALBERT_CAPTURE_SCOPE`, `ALBERT_CAPTURE_QUEUE_PATH`, `ALBERT_CAPTURE_TIMEOUT`
(capture requests, default 1 second), and `ALBERT_RECALL_TIMEOUT` (recall
requests, default 4 seconds). The encrypted queue defaults to
`~/.claude/albert/capture.db`; the adjacent state database contains only hook
identities, event classes, and sequence numbers.

The plugin uses only documented command hooks: `SessionStart`,
`UserPromptSubmit`, `PreCompact`, `Stop`, `StopFailure`, and `SessionEnd`.
Session start receives bounded, cited, delimited, explicitly non-authoritative
Albert context through Claude Code's documented `additionalContext` field. Each
submitted prompt is screened, recorded as a `user_goal`, and used as the recall
query, so the turn also receives context relevant to what was just asked. A
prompt containing detected secret material is neither recorded nor sent for
recall. Recall includes automatically captured memories; each item is labeled
with its source trust (`[verified]`, `[untrusted]`) and verified items rank first.
Pre-compaction and session-end checkpoints are idempotent. Turn outcomes use
the documented bounded `last_assistant_message`; the adapter never reads
`transcript_path`, captures hidden prompts, or sends `custom_instructions`,
absolute paths, complete transcripts, tool inputs, or error details.

`SessionStart` and `UserPromptSubmit`, which recall, have a five-second command
budget; the capture-only hooks have two seconds. The adapter exits successfully
with an empty object if configuration, policy, networking, or local state is
unavailable. Allowed events queue in the bounded encrypted shared-SDK queue.
Denied or detected-secret content is dropped before queueing. This preserves
Claude Code productivity while keeping server policy fail-closed.

## Compatibility matrix

| Claude Code version | Hook contract | Evidence | Status |
| --- | --- | --- | --- |
| 2.1.312 | Six documented command hooks, structured `SessionStart.additionalContext`, `Stop.last_assistant_message` | Plugin strict validation plus end-to-end lifecycle/security fixture | Tested |
| >=2.1.268, <2.2 | Same documented hook schemas and corrected per-hook `SessionEnd` timeout behavior | Contract-compatible; run the fixture before release on each host update | Supported contract |
| 2.1.78–2.1.267 | `StopFailure` exists, but older lifecycle timeout behavior and reported short-lived failure-hook processes reduce delivery fidelity | Session-end checkpoint remains available; failure capture is best effort | Reduced fidelity |
| <2.1.78 or >=2.2 | Required failure hook is absent, or future major/minor contract is unvalidated | No compatibility claim | Unsupported |

`StopFailure` output is observational and ignored by Claude Code. Some 2.1.x
releases have also terminated that hook process early; failure capture is
therefore best effort even where the event exists. `SessionEnd` remains the
authoritative final checkpoint. Cloud sessions do not read local user settings;
install the plugin in the cloud/self-hosted environment for hooks to run there.

The end-to-end fixture is `tests/test_claude_adapter.py`. It proves structured
start recall and citations, shared event semantics, provenance without absolute
paths, retry idempotency, pre-compaction/end checkpoints, outage continuation,
secret non-retention, plugin shape, and fail-open CLI behavior.

## Upgrade, rotation, revoke, rollback, and uninstall

Re-run `install` to upgrade, reconnect, or rotate a token. The replacement is
validated and smoke-tested before commit, retains the encrypted queue key and
queue, and restores the exact previous Albert tree if validation or proof
fails. Unsupported versions and schemas fail before filesystem changes.

`albert-claude-lifecycle revoke` deletes only Albert's credential file and
leaves the plugin available for later reconnection. `uninstall` removes only
the tree bearing Albert's ownership marker; it never edits unrelated plugins
or Claude settings. After revoke or uninstall, revoke the corresponding
credential in Albert Cloud or your self-hosted Brain when one was issued there.

The immutable wheel provenance contract is emitted and verified with
`scripts/claude-package-contract.py`. Version 2.1.312 is the released-host
fixture. Versions 2.1.78 through 2.1.311 retain an explicit reduced-fidelity
claim: `StopFailure` is observational and may be terminated early, so
`SessionEnd` remains the authoritative final checkpoint. No missing event is
inferred.
