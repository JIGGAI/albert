# Codex integration

## Automatic memory adapter

Albert uses Codex CLI's supported command-hook interface. It does not patch
Codex internals or read transcript files. The supported user-level lifecycle is:

```bash
albert-codex-lifecycle install --api-url https://brain.example
albert-codex-lifecycle doctor --smoke
```

The installer prompts for the capture credential without echoing it. Automation
may use `--token-stdin` or `--token-fd`; credentials are never accepted in argv,
ordinary environment variables, Codex configuration, logs, or diagnostics. The
credential and encrypted queue key live in the Albert-owned
`~/.codex/albert/credentials.json` file with mode `0600`. The generated adapter
wrapper is the only hook-facing bridge to that file.

The installer atomically merges Albert entries into `$CODEX_HOME/hooks.json`
(default `~/.codex/hooks.json`) and preserves unrelated keys and hooks. Existing
foreign or modified Albert commands, symlinked paths, unsafe private-file modes,
and unsupported Codex releases fail closed before replacement.

Codex asks users to review new or changed hooks before running them. Review the
installed entries and trust them through Codex's normal hook-review flow. The
installer does not approve its own hooks. Do not use
`--dangerously-bypass-hook-trust` for interactive installations.

The manual adapter path remains available for migration and requires these
secret-backed environment variables:

- `ALBERT_CAPTURE_TOKEN`: an Albert credential limited to context read and capture write.
- `ALBERT_CAPTURE_QUEUE_KEY`: a URL-safe 32-byte AES key generated by
  `albert.capture_sdk.generate_queue_key()` and stored in the operator's secret store.

Optional environment variables are `ALBERT_API_URL`, `ALBERT_WORKSPACE_ID`,
`ALBERT_CAPTURE_SCOPE`, `ALBERT_CAPTURE_QUEUE_PATH`, `ALBERT_CAPTURE_TIMEOUT`
(capture requests, default 1 second), and `ALBERT_RECALL_TIMEOUT` (recall
requests, default 4 seconds). The encrypted queue defaults to
`~/.codex/albert/capture.db`. The adjacent sequencing database contains only
hook identities, event classes, and sequence numbers.

The adapter uses these documented hooks:

- `SessionStart` starts an idempotent capture session and injects bounded, cited,
  delimited, explicitly non-authoritative project recall through `additionalContext`.
- `UserPromptSubmit` captures the bounded current user goal and injects similarly
  bounded turn-relevant recall.
- `PreCompact` records an idempotent minimized checkpoint through the shared SDK.
- `Stop` records the bounded final assistant message when present and creates an
  idempotent turn-end checkpoint.
- `Interrupt` fires instead of `Stop` when the user cancels a turn. It records a
  `failure_summary` ("Codex turn interrupted by the user.") and the same idempotent
  turn-end checkpoint, so an interrupted turn is not left unconsolidated.
- `SessionEnd` records `session_ended`, checkpoints through the final sequence, and
  calls the capture session-end endpoint, matching the Claude Code and OpenClaw
  adapters.

The two recall hooks have a five-second command budget; the others have two seconds.

The adapter ignores `transcript_path`, never reads a transcript, and does not send
the absolute `cwd`. Provenance uses only bounded Git/project facts from the shared
SDK. Detected credential content is rejected before durable queueing. Albert
outages produce an empty/no-op hook response while allowed events enter the
bounded encrypted queue for later idempotent replay.

### Compatibility and reduced fidelity

| Codex CLI version | Hook evidence | Status |
| --- | --- | --- |
| 0.167.0 | Native fixture, lifecycle/security suites, hook input schemas read from the release binary, and a normal-auth fresh-session capture/recall proof | Verified |
| >=0.166.0, newer than the verified release | Stable `hooks` feature with the same command schemas, including `Interrupt` and `SessionEnd` | Installs with a "not yet verified with Albert" warning from `install` and `doctor` |
| <0.166.0 | No stable `hooks` feature with these schemas | Refused |

The verified release is the `tested` field of `src/albert/host_targets/codex.json`
(mirrored in `codex_package.json` and `automatic_memory_release.json`). The
development team's host-compatibility check reruns the conformance suite when
Codex publishes a release and opens a pull request that moves this field with
`scripts/set-verified-host-version.py codex <version>`.

Codex CLI 0.167.0 does not expose a failure hook, so Albert never emits a
`failure_summary` for model or tool errors; it uses that class only for a turn the
user interrupted. Codex's `SessionEnd` input reports `reason` as `other` for every
exit, so the recorded reason carries no more detail than that. `PreCompact`
exposes its trigger but no message/token counts, so the checkpoint stores only
the trigger.

The end-to-end fixture is `tests/test_codex_adapter.py`. It proves bounded cited
recall, sequence and checkpoint idempotency, minimized provenance, outage
continuity, denied-secret non-retention, supported hook declarations, and session-end
and interrupt handling.

The lifecycle fixture is `tests/test_codex_lifecycle.py`. It covers clean
install, private credentials, atomic hook merging, doctor, rotation/reconnect,
failed-replacement rollback, collision and symlink rejection, credential-only
revocation, and ownership-safe uninstall. `install` is also the upgrade and
rotation operation: it preserves the encrypted queue key while replacing only
the Albert-owned target after the new Brain credential passes readiness and
capture/recall proof before and after commit.

The explicit `upgrade` and `rotate` subcommands use that same transactional
operation; `rotate --api-url ...` reconnects to a replacement Brain credential.

To revoke local use without changing Codex hooks, run
`albert-codex-lifecycle revoke`. To remove Albert, run
`albert-codex-lifecycle uninstall`; it removes only the exact adapter commands
recorded by the ownership marker and the `~/.codex/albert` tree. If the commands
were modified, uninstall fails closed instead of deleting foreign state.

Release `albert-memory==0.4.0` is verified with Codex `0.167.0` and installs on
`>=0.166.0`; newer, not yet verified releases install with a warning. The installed marker records host-target descriptor
version `1.0.0`. Immutable release provenance is GitHub OIDC DSSE plus SHA-256,
declared in `src/albert/codex_package.json` and
`src/albert/host_targets/codex.json`. Codex still has no failure hook;
installation does not claim otherwise.

## MCP tools

Codex can connect to Albert over local stdio or streamable HTTP. Prefer stdio
when Codex and Albert run on the same trusted host.

## Local stdio

Add this to `~/.codex/config.toml`:

```toml
[mcp_servers.albert]
command = "albert-mcp"
args = ["--transport", "stdio"]
env = { ALBERT_API_URL = "http://127.0.0.1:8080", ALBERT_MCP_API_KEY = "REPLACE_FROM_SECRET_STORE" }
```

Use the absolute path to `albert-mcp` if it is not on the environment inherited
by Codex. Protect the config file if a key is placed in it; an environment or
secret-injection mechanism is preferable.

## Streamable HTTP

For an internal, protected endpoint:

```bash
codex mcp add albert --url https://memory.internal.example/mcp
codex mcp list
```

Equivalent configuration:

```toml
[mcp_servers.albert]
url = "https://memory.internal.example/mcp"
bearer_token_env_var = "ALBERT_API_KEY"
```

Set `ALBERT_API_KEY` in Codex's environment through your secret manager. Codex
sends its value as the HTTP bearer token, and Albert retains that principal's
identity and capabilities. This setting follows the
[official OpenAI MCP credential guidance](https://developers.openai.com/api/docs/guides/agents-api/tools/plugins#authenticate-mcp-servers).

## Project instructions

Copy [AGENTS.example.md](AGENTS.example.md) to the project root as `AGENTS.md`,
then adjust project and resource naming. The MCP connection makes tools
available; the instructions tell Codex when and why to use them.

Restart the client or begin a new session after configuration changes, then ask
Codex to list Albert's tools and run a narrowly scoped `memory_search`.

Reference: [OpenAI's MCP documentation](https://developers.openai.com/learn/docs-mcp).
