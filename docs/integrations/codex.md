# Codex integration

## Automatic memory adapter

Albert uses Codex CLI's supported command-hook interface. It does not patch
Codex internals or read transcript files. Install the Albert Python package,
then copy `src/albert/codex_hooks/hooks.json` to the `hooks.json` location for
the desired Codex configuration layer (for example, `$CODEX_HOME/hooks.json`
for the user layer or `.codex/hooks.json` for a trusted project layer).

Codex asks users to review new or changed hooks before running them. Review the
fixture and trust it through Codex's normal hook-review flow. Do not use
`--dangerously-bypass-hook-trust` for interactive installations.

Required secret-backed environment variables:

- `ALBERT_CAPTURE_TOKEN`: an Albert credential limited to context read and capture write.
- `ALBERT_CAPTURE_QUEUE_KEY`: a URL-safe 32-byte AES key generated by
  `albert.capture_sdk.generate_queue_key()` and stored in the operator's secret store.

Optional environment variables are `ALBERT_API_URL`, `ALBERT_WORKSPACE_ID`,
`ALBERT_CAPTURE_SCOPE`, `ALBERT_CAPTURE_QUEUE_PATH`, and
`ALBERT_CAPTURE_TIMEOUT`. The encrypted queue defaults to
`~/.codex/albert/capture.db`. The adjacent sequencing database contains only
hook identities, event classes, and sequence numbers.

The adapter uses these documented hooks:

- `SessionStart` starts an idempotent capture session and injects bounded, cited,
  delimited, explicitly non-authoritative project recall through `additionalContext`.
- `UserPromptSubmit` captures the bounded current user goal and injects similarly
  bounded turn-relevant recall.
- `PreCompact` records an idempotent minimized checkpoint through the shared SDK.
- `Stop` records the bounded final assistant message when present and creates an
  idempotent turn-end checkpoint.

The adapter ignores `transcript_path`, never reads a transcript, and does not send
the absolute `cwd`. Provenance uses only bounded Git/project facts from the shared
SDK. Detected credential content is rejected before durable queueing. Albert
outages produce an empty/no-op hook response while allowed events enter the
bounded encrypted queue for later idempotent replay.

### Compatibility and reduced fidelity

| Codex CLI version | Hook evidence | Status |
| --- | --- | --- |
| 0.135.0 | Native fixture plus lifecycle, outage, policy, provenance, and idempotency tests | Tested |
| >=0.135.0, <0.136.0 | Stable `hooks` feature with the same command schemas | Supported contract; rerun the fixture for each release |
| <0.135.0 or >=0.136.0 | Not validated by this adapter release | Unsupported until conformance passes |

Codex CLI 0.135.0 does not expose a session-end or failure hook. Consequently,
Albert creates turn-end checkpoints at `Stop`, but it cannot truthfully emit a
`session_ended` or `failure_summary` event or call the capture session-end
endpoint. This is an explicit reduced-fidelity state, not an inferred event.
`PreCompact` exposes its trigger but no message/token counts, so the checkpoint
stores only the trigger.

The end-to-end fixture is `tests/test_codex_adapter.py`. It proves bounded cited
recall, sequence and checkpoint idempotency, minimized provenance, outage
continuity, denied-secret non-retention, supported hook declarations, and the
disclosed unavailable lifecycle behavior.

## MCP tools

Codex can connect to Albert over local stdio or streamable HTTP. Prefer stdio
when Codex and Albert run on the same trusted host.

## Local stdio

Add this to `~/.codex/config.toml`:

```toml
[mcp_servers.albert]
command = "albert-mcp"
args = ["--transport", "stdio"]
env = { ALBERT_API_URL = "http://127.0.0.1:8080", ALBERT_MCP_API_KEY = "REPLACE_FROM_SECRET_STORE" }
```

Use the absolute path to `albert-mcp` if it is not on the environment inherited
by Codex. Protect the config file if a key is placed in it; an environment or
secret-injection mechanism is preferable.

## Streamable HTTP

For an internal, protected endpoint:

```bash
codex mcp add albert --url https://memory.internal.example/mcp
codex mcp list
```

Equivalent configuration:

```toml
[mcp_servers.albert]
url = "https://memory.internal.example/mcp"
bearer_token_env_var = "ALBERT_API_KEY"
```

Set `ALBERT_API_KEY` in Codex's environment through your secret manager. Codex
sends its value as the HTTP bearer token, and Albert retains that principal's
identity and capabilities. This setting follows the
[official OpenAI MCP credential guidance](https://developers.openai.com/api/docs/guides/agents-api/tools/plugins#authenticate-mcp-servers).

## Project instructions

Copy [AGENTS.example.md](AGENTS.example.md) to the project root as `AGENTS.md`,
then adjust project and resource naming. The MCP connection makes tools
available; the instructions tell Codex when and why to use them.

Restart the client or begin a new session after configuration changes, then ask
Codex to list Albert's tools and run a narrowly scoped `memory_search`.

Reference: [OpenAI's MCP documentation](https://developers.openai.com/learn/docs-mcp).
